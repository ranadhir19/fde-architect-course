# FDE 1.05 Exercise — Cut a 14-item wish list to a 4-item v1

**Topic:** Scoping and saying no (Layer 2). **Part (d) of FDE 1.05.**
Attempt this before watching the tutorial half of the lesson.

## The task

Read `wishlist-and-constraints.md`. It holds the 14-item wish list
Cedarbrook Home Goods (the fictional Capstone 1 customer) brought to
the scoping meeting, the constraints the engagement actually runs
under, and the value hypothesis you framed in FDE 1.04. Every item
on the list is wanted by someone named. None of them is stupid.
That is what makes this a scoping exercise and not a sorting one.

Write `scope-document.md` from `scope-document-template.md`. It must
contain:

- A v1 of exactly four items, sequenced in the order you would ship
  them, each tied to the value hypothesis or to a stated prerequisite
  for testing it.
- A "not in v1" list covering the other ten items, each with a written
  reason for the cut that names the criterion used — value, evidence,
  dependency, ownership, or risk — and the condition under which the
  item would be reconsidered.
- One paragraph addressed to the stakeholder whose item was cut and
  who will push back hardest, written so it can be sent as-is: it
  acknowledges what they asked for, states the cut and the criterion,
  and names what happens instead.
- The engagement that cannot succeed: from the constraints, name the
  one condition that, if it cannot be changed, means the scoped v1
  still should not start — and say what you would recommend instead.

## Done means

- v1 has exactly four items. A fifth item smuggled in as a
  "quick win" or a sub-bullet scores zero for the whole document.
- Every cut has a reason a reader can argue with. "Out of scope" and
  "phase two" are not reasons.
- No v1 item contradicts the FDE 1.04 hypothesis: v1 tests that
  hypothesis first, in its cheapest form, before any build the
  hypothesis has not yet justified.
- Graded with `RUBRIC.md`. `SOLUTION.md` is the reference answer,
  released after the attempt window.
