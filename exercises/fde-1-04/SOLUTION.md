# FDE 1.04 Reference solution

Released after the attempt window. One defensible framing:

**Workflow.** Agents answering "where is my refund" questions. It is
31% of ticket volume in the hand-counted week, it is the workflow the
agents themselves named first, and unlike "support" as a whole it can
be counted, baselined, and changed. The category-taxonomy problem is
real but it is a measurement problem; framing it as the value
hypothesis would promise a better spreadsheet, not a moved number.

**Baseline.** Returns questions: 31% of tickets, hand-counted sample
week, categories corrected by the answering agents (source: discovery
shadowing counts). First-response time across all tickets: 9.5 hours,
ticket export, last 90 days. Cost per ticket: unknown — measure first
by asking Finance for agent cost per hour and timing a sample of
returns tickets end to end. The 40% as-filed growth figure is not used
as a baseline anywhere: discovery showed it overstates real demand
growth because of the merged legacy category.

**Intervention.** Publish one returns answer the agents and the
warehouse both sign: reconcile the policy page with warehouse practice
on the refund window, and give agents a single checked answer path for
returns questions, so the second-source check disappears. Note what
this intervention is: a policy reconciliation plus an answer path.
No model, no automation — the framing step does not get to assume the
build. If a later build is justified, it is justified by this
hypothesis being tested first in its cheapest form.

**Predicted delta.** Median handling effort on returns questions
falls, visible first as first-response time on returns tickets
dropping from the all-ticket baseline of 9.5 hours toward 6 hours
within four weeks of the reconciled answer shipping — argued from the
removed second-source check on most returns tickets. Volume of
returns questions may not fall at all; the hypothesis is about effort
per question, and says so.

**Falsifier.** If, four weeks after the reconciled answer ships, a
hand-counted sample week shows returns tickets still needing the
second-source check at the same rate as the discovery week, the
hypothesis is wrong: the cost was never the disagreement, and the
recommendation is to stop work on this workflow and re-frame around
the walk-up queue (118 unrecorded tickets in the discovery week) —
the other workflow discovery surfaced with a countable baseline.

**Owner.** The operations manager: owns the returns policy, confirmed
the disagreement in interview, and is the only role that can sign the
reconciled answer. The sponsor gets the board number from this test,
not from a promise made before it.

**Kill criteria.** One: if the operations manager will not sign a
single reconciled returns answer within two weeks, stop — the
engagement's cheapest test is blocked by ownership, and no build
fixes that. Two: if the hand-count on a second sample week shows
returns questions under 10% of volume (the first week was seasonal),
stop and re-run discovery framing before any scope is signed.
