# REVIEW.md — the security questionnaire, answered at the strength the evidence supports (template)

Hand this to the customer's security team. Every number
comes from your own run of `review.py` over
`questionnaire.json` as delivered. The verdict comes
first: a return that opens with a supported count has
buried its own decision.

## The verdict

- Verdict, with its rule. The gate gap ids, named on
  their own line, and for each one the work that
  closes it and the submission consequence until
  it does.

## The overclaims, corrected

- Each overclaim: the question, what the draft claimed,
  what the evidence supports, and the corrected answer
  as returned. Corrections are shown, not silent — a
  reviewer who finds a silent edit assumes there are
  others.

## The gate questions

- Each gate question: its status, the rule that
  produced it, and — for a gap — the artefact or
  action that closes it, stated as work, not as
  reassurance.

## The full questionnaire

- All sixteen questions, grouped by status. For each:
  the answer as returned, the artefact named for it,
  its age against its maximum where it exists, whether
  it covers the whole question, and its owner or the
  blank where nobody is named.
- Per section: which questions stand supported and
  which do not, so each of the reviewer's section
  owners can read their own part without re-deriving it.

## The qualifications

- Each partial or stale non-gate answer, returned as
  a qualification: what the evidence covers, what it
  does not, what closes the gap, and who owns the
  closing work.

## What this pack does not claim

- One line: a status is a claim about the artefacts
  as the workshop recorded them. What would change
  the pack — an artefact produced, a register rebuilt,
  an exercise run — and how the pack would be
  recomputed when it does.
